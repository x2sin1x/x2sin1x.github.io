## DFlash 槽位映射

DFlash 展示了这个模板最关键的节奏。完整成稿见 [examples/DFlash.md](../examples/DFlash.md)。这里的映射用于理解各段承担的功能，不应被当作其他论文的固定内容。

| 模板槽位 | DFlash 中的填法 | 叙事作用 |
|---|---|---|
| 开场瓶颈 | 自回归生成逐 token 串行；现有 speculative decoding 的 drafter 仍是串行 | 把“LLM 推理慢”收紧为 drafter 瓶颈 |
| 开场主张 | 轻量 block diffusion 一次并行起草整块 token，并接受 target hidden features 条件 | 在解释细节前给出方法轮廓 |
| 朴素替代失败 | 大型 diffusion drafter 成本高；无 target conditioning 的五层小 drafter 只有约 2-3x 加速 | 证明“换成 diffusion”本身不是答案 |
| 转折设问 | 能否让 drafter 同时足够小、足够准？ | 把两类失败合并成一个研究问题 |
| 关键洞察 | target model 的 hidden features 已包含未来 token 信息 | 让小 drafter 不必从零预测 |
| 权衡变化 | 自回归 draft cost 随 token 数线性增长；block diffusion 在一次前向中并行预测 | 解释为什么更深 drafter 仍可能更快 |
| 设计机制 | feature fusion、逐层 KV injection、parallel drafting | 将洞察落到三步数据流 |
| 主证据 | Qwen3 非思考模式下平均 4.9x 自回归 baseline 加速；相对 EAGLE-3(16) 为 2.4x | 用同一设置下的总体结果闭环 |
| 补充证据 | sampling、thinking mode 与 SGLang 并发结果 | 说明收益不只存在于单一解码设置 |
| 结尾重构 | diffusion model 不必独立取代 autoregressive LLM，也可成为受验证的并行 drafter | 从方法结果上升到角色分工变化 |

## 模板使用禁区

- 不要为所有论文强行加入 Quick Start、设问或三项机制。
- 不要将“最高结果”放进开场却省略取得该结果的模型、任务和设置。
- 不要把作者对领域的愿景写成实验已经证明的结论。
- 不要为了像博客而省略 baseline 公平性、负面结果或关键限制。
- 不要逐句改写 DFlash 示例；借用的是节奏和信息密度，不是措辞。
