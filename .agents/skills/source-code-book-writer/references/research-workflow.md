# 源码研究工作流

本流程用于完整书稿和多章源码系列。目标不是穷举文件，而是建立可以从入口追到结果、从结论追回血缘证据的系统模型。

## 1. 固定研究对象

先记录：

| 字段 | 内容 |
|---|---|
| 仓库 | URL 或本地路径 |
| 版本 | branch / tag |
| 快照 | 完整 commit SHA |
| 核对日期 | 当地日期 |
| 交付范围 | 全仓、子系统或版本差异 |
| 目标读者 | 使用者、贡献者、架构师或运维人员 |

远程默认分支会移动，不能作为精确引用锚点。存在多个实现世代时，先确认当前入口落在哪一代，不要把旧实现与新实现拼成一条调用链。

## 2. 建立仓库地图

运行 `repo_inventory.py` 获得第一轮清单，然后核对：

- 语言、工作区与包边界；
- 构建、依赖、配置和发布清单；
- CLI、服务、库 API、插件等外部入口；
- 核心类型、状态容器、注册表和工厂；
- 测试、示例、基准与迁移文件；
- 生成代码、vendor 和历史兼容层。

用一句话定义每个核心模块的职责，并标出依赖方向。若一句话需要多个“以及”，该模块可能仍需拆分。

## 3. 追踪黄金路径

至少追踪一条能解释项目主要价值的端到端路径。根据项目选择：

- CLI：参数解析 -> 配置 -> 命令分发 -> 核心服务 -> 输出；
- Web/API：路由 -> 校验 -> 业务编排 -> 存储/外部调用 -> 响应；
- Agent：消息 -> 上下文 -> 模型 -> 工具 -> 状态更新 -> 回复；
- 数据库：写入 -> 编码/索引 -> 持久化 -> 查询计划 -> 检索/合并；
- 推理引擎：请求 -> 调度 -> KV/内存分配 -> 模型执行 -> 采样 -> 流式返回；
- 协议：握手 -> 能力协商 -> 请求/通知 -> 状态转换 -> 错误与关闭。

为每一跳记录：

`触发事件 -> 调用者 -> 被调符号 -> 输入/状态变化 -> 下一跳 -> 失败分支`

不要只阅读定义。至少查找一个真实调用点和一个测试、示例或配置入口；抽象类还要找到主要实现和选择实现的工厂或注册逻辑。

## 4. 补齐系统维度

黄金路径解释“怎么跑”，下列维度解释“为什么能长期运行”：

- 生命周期：创建、复用、关闭、清理；
- 状态所有权：可变状态由谁持有，跨请求如何隔离；
- 并发：任务、线程、锁、队列、背压和取消；
- 持久化：数据模型、事务、一致性、恢复和迁移；
- 扩展：接口、hook、插件发现、依赖注入和兼容层；
- 安全：信任边界、授权、隔离、敏感数据和危险执行；
- 性能：热路径、缓存、批处理、内存布局和网络边界；
- 可观测性：日志、指标、追踪、错误传播和诊断入口。

只写与项目实际相关的维度。没有源码证据的“企业级”“高性能”“安全”不是分析结论。

## 5. 维护证据账本

账本用于写作前校验，不必原样放入正文：

| 结论 | 证据类型 | 符号 | `path:line` | 调用点/测试 | 性质 | 置信度 |
|---|---|---|---|---|---|---|
| 请求先经过策略过滤 | 实现 + 测试 | `Policy.apply` | `src/policy.ts:84` | `router.ts:31` / `policy.test.ts:42` | 事实 | 高 |

“性质”使用：

- &#8203;**事实**&#8203;：代码、配置或测试直接可见；
- &#8203;**解释**&#8203;：对多处事实的机制性归纳；
- &#8203;**推断**&#8203;：合理但未由项目直接声明，需要限定措辞；
- &#8203;**未知**&#8203;：当前快照无法确认。

中心结论至少需要实现证据；涉及可观察行为时再用测试或示例交叉验证。涉及设计动机时优先查看注释、ADR、issue、PR 和提交历史，找不到就将其表述为推断。

## 6. 从证据生成目录

为每个候选章节写一张卡片：

| 字段 | 问题 |
|---|---|
| 读者问题 | 读完能回答什么？ |
| 前置章节 | 需要先理解哪些概念？ |
| 主路径 | 本章追踪哪条调用链或状态转换？ |
| 核心符号 | 哪 3–8 个符号足以支撑？ |
| 关键图 | 哪种关系用图比文字更清楚？ |
| 取舍 | 获得了什么，又付出什么？ |
| 边界 | 哪些情况不适用或会失败？ |

无法填写“主路径”和“核心符号”的章节通常只是主题标签，应继续研究、与相邻章节合并或删除。

## 7. 引用与版本处理

- 代码引用以固定 commit 为准，逐字复制后再删减；省略处用明确省略标记，不能改变控制流含义。
- 本地引用写 `path:line` 和符号名；公开仓库可增加 `https://github.com/<owner>/<repo>/blob/<sha>/<path>#Lx-Ly` 永久链接。
- 精确数量必须可重算并说明口径，例如“注册了 12 个内置工具”应说明是否包含别名和条件注册项。
- 比较版本时分别建立证据账本，不从文件名相似推断行为相同。
- 发现源码、测试和文档不一致时，呈现差异及快照时间，不替项目擅自裁决意图。
