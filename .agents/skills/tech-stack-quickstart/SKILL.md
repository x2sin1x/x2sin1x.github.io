# 技术栈快速入门指南 (Tech Stack Quickstart)

为指定的技术/框架/库/工具生成一份全面、结构化、新手友好的快速入门和用法参考文档。

## 核心原则

### 1. 面向新手
- 假设读者是刚接触该技术的新手，但有基本的编程常识
- 解释每一个专业术语的首次出现
- 避免"想当然"的前提知识——如果必须依赖前置知识，明确指出并快速补充说明
- 使用类比和对比帮助理解抽象概念

### 2. 搜索先行，确保准确
- **必须先用 WebSearch 搜索**以下信息：
  - 该技术的当前最新稳定版本
  - 官方推荐的安装方式和系统要求
  - 最新的 API/语法变化（如果有 breaking changes）
  - 官方文档的快速入门示例
  - 当前社区推荐的最佳实践
- 搜索后验证信息的一致性和时效性
- 在文档中标注版本信息："本文档基于 XX v1.2.3"

### 3. 示例驱动
- 每个概念/API 都必须配可运行的代码示例
- 示例代码要完整（能直接复制运行或几乎可以直接运行）
- 示例输出要一并展示
- 用代码注释解释关键部分

### 4. 对齐官方文档结构
- **搜索官方文档时，重点分析其目录结构和章节组织方式**
- 生成的文档应当映射官方文档的知识组织脉络，而不是自创一套全新的分类
- 这样做的好处是：用户后续查阅官方资料时能自然衔接，术语和概念位置都对得上
- 具体做法：
  - 搜索时找到官方文档的目录/导航结构
  - 提炼官方文档的核心章节划分
  - 在保持新手友好（简化、加示例、加解释）的前提下，尽量沿用官方的章节顺序和命名
  - 如果官方结构对新手来说入口太深，可以调整顺序，但要在文中注明"参见官方文档 XX 章节"

### 5. 结构化输出
文档结构应包含以下章节（可根据技术类型和官方文档结构适当调整顺序和内容）：

## 工作流程

当用户触发此技能时，按以下流程执行：

### Step 1: 确认需求
向用户简要确认：
- 具体的技术名称和范围（如用户说"React"，确认是 React.js 而不是 React Native）
- 是否有特定版本需求
- 是否有特定的关注点（如只需要安装部分，或只需要 API 参考）
- 输出保存路径（如果用户没指定，保存到当前工作目录）

### Step 2: 联网搜索与分析官方文档结构

使用 WebSearch 搜索以下内容（并行搜索效率更高）：

**必须搜索**：
1. `[技术名] 官方文档` — 找到官方文档网站入口
2. `[技术名] documentation [版本号] getting started`
3. `[技术名] 最新版本 安装`

**重点分析**：打开官方文档后，仔细分析其：
- **目录结构**：官方将概念分成了哪些主要章节？顺序如何？
- **术语体系**：官方使用了什么术语和命名？
- **示例风格**：官方示例的代码风格是怎样的？

**辅助搜索**：
4. `[技术名] best practices [年份]`
5. `[技术名] 常见错误 新手`（遇到中文用户时）
6. `[技术名] cheatsheet`

如果是英文技术但用户用中文提问，优先搜索中英文资料结合使用。对搜索到的信息做交叉验证。

### Step 3: 生成文档

根据搜索到的官方文档结构和信息，按照输出模板生成完整的 Markdown 文档。

**结构映射原则**：
- 先列出从官方文档中提取的章节结构
- 在输出模板的基础上，按官方文档的组织方式来排列核心概念的顺序
- 在每个章节开头注明"对应官方文档：[章节名](链接)"，方便用户对照查阅
- 如果官方结构对新手来说不友好（例如官方将安装说明放在附录），可以提前，但要注明

生成时的注意事项：
- **版本一致性**：全文使用的版本号要统一
- **代码可运行性**：所有代码示例要保证语法正确、逻辑自洽
- **渐进难度**：从简单到复杂排列概念
- **中英文混排**：技术名词保留英文，解释用中文。如果用户用英文提问，全英文输出
- **链接标注**：引用来源时标注链接，方便读者深入阅读

### Step 4: 保存并报告
- 将文档保存到指定路径（或当前目录），文件名为 `[技术名]-quickstart.md`
- 向用户报告文档已生成并简要说明文档包含的内容概要

## 输出格式要求

- 使用 GitHub 风格 Markdown
- 用 `---` 分隔主要章节
- 表格要排版整齐
- 代码块标注语言类型
- 使用引用块(`>`)放置提示信息
- 使用 ✅ / ❌ 标记对/错做法
- 所有代码示例要有输出展示

## 适用范围

| 技术类型 | 示例 | 说明 |
|---------|------|------|
| 编程语言 | Python, Rust, Go, TypeScript | 侧重语法、类型系统、标准库 |
| 框架 | React, Vue, Django, Spring Boot | 侧重架构理念、核心 API、项目结构 |
| 工具 | Docker, Git, Webpack, Vite | 侧重安装配置、常用命令、工作流程 |
| 数据库 | PostgreSQL, MongoDB, Redis | 侧重 CRUD、查询语法、数据模型 |
| 云服务 | AWS S3, Kubernetes, Terraform | 侧重核心概念、CLI 命令、配置写法 |
| 库/包 | Pandas, NumPy, Lodash, Axios | 侧重核心 API、常用函数、使用模式 |

根据技术类型调整模板中各章节的侧重点和篇幅。

## 注意事项

- 不要生成未经搜索验证的版本号和安装命令
- 如果搜索到矛盾的信息，列出不同选项并说明差异，不要武断选择其一
- 对于大型技术（如 Kubernetes），建议用户聚焦于某个子主题而非面面俱到
- 如果用户提到的技术已过时或有更好的替代，在简介中友好地指出并推荐替代方案
