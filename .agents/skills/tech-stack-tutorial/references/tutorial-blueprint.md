# 技术教程编排蓝图

完整教程、课程式教程或多章节文档使用本蓝图。按技术类型裁剪，不要求机械包含全部章节。

## 一、推荐信息架构

### 起步区

1. **教程首页**：一句话解释技术、目标读者、学完能做什么、适用版本、预计前置知识。
2. **学习路线**：用有序列表列出从安装到项目实践的章节依赖；指出可跳过和必须学习的部分。
3. **环境搭建**：系统要求、安装、版本验证、编辑器或工具选择、最小故障排查。
4. **第一个可运行示例**：从新建目录或文件开始，给出命令、完整代码、运行方式和预期输出。

### 基础区

按概念依赖逐章展开，每章只承担一个主要学习目标。典型顺序为：

- 基本语法或配置结构
- 核心数据/对象模型
- 控制流、生命周期或请求流程
- 模块化、组件化或项目组织
- 输入输出、状态、错误处理
- 常用标准库、核心 API 或命令

### 实战区

- 用一个贯穿式小项目串联基础概念。
- 先描述成品与目录结构，再逐步实现。
- 每一步说明新增内容、运行方法和可观察结果。
- 加入一个真实错误场景及其诊断方法。

### 提升区

- 测试、调试、日志和性能基础
- 安全、配置、依赖与部署注意事项
- 常见陷阱、版本迁移和最佳实践
- 常用操作速查表
- 下一步路线与官方资源

## 二、按技术类型选章

### 编程语言

重点覆盖运行模型、变量与类型、运算符、控制流、函数、集合、模块、输入输出、异常、面向对象或该语言特有范式、包管理和测试。不要把标准库清单当作教程主体。

### Web 或应用框架

重点覆盖脚手架与目录结构、入口与生命周期、路由/组件/控制器、状态或数据访问、配置、错误处理、测试、构建与部署。用一个可运行应用贯穿教程。

### 库或 SDK

重点覆盖安装与初始化、核心对象、最常见调用路径、参数与返回值、错误模型、异步或并发行为、与宿主项目的集成。避免逐项复述 API 索引。

### 数据库与数据工具

重点覆盖安装或连接、数据模型、CRUD、查询、索引、事务、一致性、备份恢复和安全。示例数据应小而完整，查询结果要可核对。

### CLI、构建或 DevOps 工具

重点覆盖安装、配置文件、命令结构、常用工作流、自动化、日志排查、权限与回滚。明确命令在哪个目录执行以及它会修改什么。

### 云平台或托管服务

先解释资源模型、账户/权限和可能费用。默认使用本地模拟、免费层说明或只读示例；任何真实创建、部署、删除或计费操作都需要用户明确授权。

~~~markdown

> 本节目标：[读者完成本节后能做什么]

[先通俗解释，再给准确含义；说明它与上一节的关系。]

## 基本语法或操作

```language
[最小完整示例]
```

运行：

```shell
[命令]
```

预期结果：

```text
[稳定、可复现的输出]
```

## 逐步解释

1. [关键步骤及原因]
2. [关键步骤及原因]

## 实际用法

[在真实小场景中扩展示例，避免只更换变量名。]

## 常见错误

- **现象**：[错误或症状]
- **原因**：[根因]
- **修复**：[最小修复方法]

## 小结

- [本节最重要的 2–4 点]

## 练习

~~~

根据内容删去不适用的小节；不要为了填模板制造虚假的输出、错误或练习答案。

## 四、写作风格

- 标题直接使用技术术语，如“Python 列表”“Docker 镜像”，避免含糊标题。
- 段落保持短小，一段解决一个问题；复杂操作使用编号步骤。
- 用“示例”“运行结果”“注意”“常见错误”等稳定标签帮助扫描。
- 中文解释保留必要英文术语，并在首次出现时说明含义。
- 比喻只用于建立直觉，随后必须回到准确机制。
- 语气清楚、友好、直接；避免营销语、空泛赞美和无依据的“最佳”。
- 不复制第三方教程的句子、示例项目或独特目录；重新组织并基于权威事实独立写作。

## 五、来源与链接

- 教程开头注明版本和最后核对日期。
- 关键安装、兼容性、弃用和安全信息优先链接官方来源。
- 不需要为每句常识加引用；对可能变化或存在争议的事实提供链接。
- 若多个权威来源不一致，明确写出差异及适用条件。

## 六、交付前质量检查

- [ ] 标题、目录和章节顺序形成清楚的学习路径。
- [ ] 读者可从空目录或明确的起始状态复现第一个示例。
- [ ] 代码包含必要的导入、依赖、文件名和运行命令。
- [ ] 预期输出没有把随机值、时间、平台差异写成固定结果。
- [ ] 同一教程没有混用不兼容版本的语法或 API。
- [ ] 重要概念同时回答“是什么、为什么、怎么用、哪里会错”。
- [ ] 实战项目确实复用了前文概念，而不是突然引入大量未解释内容。
- [ ] 安全、费用、数据删除和外部副作用有醒目标注。
- [ ] 结尾提供可执行的下一步，而不是宽泛的资源堆砌。
