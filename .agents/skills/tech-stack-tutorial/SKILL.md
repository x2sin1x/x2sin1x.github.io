# 技术栈教程生成器

围绕用户指定的技术栈，编写可从头学习、也可按目录查阅的教程。借鉴教程网站清晰分类、短章节、语法—示例—结果—练习的教学节奏，但不要复制其原文或固有表达。

## 确定范围

从请求中提取技术名称、版本、读者基础、目标场景、操作系统、篇幅和交付形式。缺失时采用合理默认值：面向有基础编程常识的初学者，覆盖当前稳定版本和最常用工作流，以中文 Markdown 输出。

仅当歧义会显著改变教程时提问，例如同名技术、互不兼容的大版本，或“完整教程”的范围明显过大。大型技术默认先给出完整学习路线，再深入最常用的基础路径，并说明未展开的边界。

## 查证资料

在写作前查阅可用的最新资料：

1. 以官方文档、官方发布说明、官方仓库或标准规范作为版本、安装命令、API 和行为的事实基线。
2. 用可信教程、社区文档或问答资料补充新手常见困难与教学顺序；教程网站只用于参考信息架构和讲解节奏。
3. 对版本号、系统要求、安装方式、已弃用功能和易变化的命令进行交叉核对。
4. 明确教程适用的版本或日期。找不到可靠版本信息时说明不确定性，不要猜测。

优先沿用官方术语和概念依赖关系。如果官方目录不适合新手，可以调整教学顺序，但不要改变概念含义。

## 设计教程

先建立从入门到实际使用的学习路径，再写正文。需要完整教程、系列文章或多章节文档时，读取 [references/tutorial-blueprint.md](references/tutorial-blueprint.md)，按技术类型选择章节，并使用其中的页面模板与质量检查表。用户只要求短教程时，可缩减章节，但保留可运行示例和下一步指引。

教程应体现这些特征：

- 目录清晰，章节标题能直接说明学习目标；单节聚焦一个主要概念。
- 首次出现术语时用通俗语言解释，再给准确技术定义。
- 先展示最小可运行示例，再逐步增加真实场景、参数和边界条件。
- 代码块标注语言；命令注明运行目录或前置条件；结果可稳定预测时展示预期输出。
- 将“为什么这样做”“何时使用”“常见错误”放在相关示例附近。
- 适量使用提示、警告、表格和对比；不要用装饰性元素淹没正文。
- 每章末提供小结、练习或下一章衔接。不要承诺不存在的在线运行器。

## 验证

在环境允许且成本合理时运行关键安装命令之外的最小示例、测试代码或构建步骤。不要执行会改动外部系统、产生费用或需要敏感凭据的验证。

交付前检查：版本和术语一致；示例之间可衔接；依赖与文件结构完整；输出与代码匹配；链接指向权威或确有补充价值的资料。未实际运行的示例应标注为静态检查或示意代码，不要声称已经验证。

## 交付

按用户要求在对话中输出，或保存为单个 Markdown 文件/多文件教程。用户未要求文件时不要擅自创建大型文档目录。若篇幅超过单次回答的合理长度，先交付目录和第一阶段内容，并清楚列出后续章节，而不是压缩成泛泛摘要。

结尾给出官方文档、版本说明和少量高价值延伸资源，并简要说明各资源适合解决什么问题。
